에디터 MCP로 명령을 실행할 때의 규칙과, 컴파일 확인이 놓치는 것들.

**작성 규칙**
- 결과는 콘솔 출력이 아니라 파일로 써서 읽는다. 긴 출력이 잘리는 것을 피하기 위해서다.
- 리플렉션은 쓰지 않는다. 에디터 버전에 따라 조용히 실패한다.
- 에디터가 재생 중이면 컴파일을 요청하지 않는다. 사람이 쓰고 있을 수 있다. 재생 상태를 먼저 확인한다.

**컴파일 확인 방법**
어셈블리 수정 시각 변화, 산출물에서 심볼 검색, 콘솔 에러 수집을 함께 본다. 한 가지만으로는 신뢰할 수 없다.

**이 방법이 놓치는 것**
- enum 값 변경은 잡히지 않는다
- 어셈블리 경계를 넘는 변경은 단독으로 확인할 수 없다
- 새로 추가한 파일은 기존 컴파일 목록에 없어 확인 대상에서 빠진다

**왜 적어 두는가:** 확인 수단이 우회적이면 실패가 조용히 지나간다. 위 세 가지에 걸리는 변경은 "검증하지 못한 것"으로 커밋 본문에 명시하고, 사람이 직접 확인하도록 표시한다.
